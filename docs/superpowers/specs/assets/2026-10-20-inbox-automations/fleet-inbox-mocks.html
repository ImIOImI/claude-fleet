01Inbox entry point: variants

Why the first version was off

It used an unstyled button next to the real Settings gear, plus a red count bubble. The strip's own rule (#23) is that state rides on a dot, never on pill or bubble chrome, and labels are small mono text.

What stays the same

Placement and behavior: clicking opens the inbox in the main pane. Only the control changes.

A · Inbox chip (chosen)

A compact chip in the same language as the workspace chips: status dot, name, sub-line. It sits after the workspaces, before +. Selected, it gets the active chip treatment, so "the inbox is where you are" reads like any workspace. While the inbox is open, the workspace chip drops its active outline so only one place looks selected; the rails keep showing the last workspace.

02Inbox › Todos

Where it lives

A tray icon sits beside Settings in the top strip, with an open-count badge that turns red when anything is urgent. Clicking it swaps the main pane to the inbox. Both rails stay as you left them.

Three tabs

They use the session-tab strip: Todos, Automations, Activity. The Activity count is violet, the app's "needs you" color, because it counts pending approvals.

Rows

Grouped by priority, with a colored left edge (urgent red, high amber). The meta line shows source (⟳ automation, a colored dot for a workspace, or You), age, seen-count, a recurred flag and tags.

Detail

Shows the immutable source and its run, the dedupe key, seen history, the linked session and editable tags. Below that is the poster's markdown body and a history timeline that explains why the todo reopened.

04Global snooze & downtime

Pause vs. downtime

Pause is one-off and immediate ("for 1 hour"). Downtime is a recurring schedule ("nights 22:00 to 07:00"). Both only hold notifications. Todos still arrive.

Urgent bypass

Each pause and each downtime decides whether urgent items get through. Off by default for nights, on for focus blocks.

One summary afterwards

When it ends you get one digest, never a burst of replayed toasts.

Where to pause everything

Two entry points that set the same global pause: the header control (with the menu from the earlier chip option) while you're in the inbox, and the tray when the window is closed. If a pause and a downtime disagree about urgent items, the most recent explicit action wins: a pause that holds urgent overrides a downtime that lets it through.

Inbox header control, with the menu chosen

The header button always shows the current state. Clicking it opens a menu: quick durations with hints, the urgent bypass, and the schedules. While paused, the same menu switches to resume and extend.

06Sessions in the Inbox

The Inbox is the automations workspace

Its terminal sessions open as tabs after Todos, Automations and Activity, with + for a new one. Ask questions about automations, investigate failures, or make bulk changes right next to them.

Rails follow

With the Inbox selected, the left rail lists the automations workspace's sessions and the Observability rail shows its cost and context, like any workspace.

Fleet-wide reach, same approvals

Its role grants read access to every automation and run, and lets it propose changes to any of them. Changes still flow through proposals; it never approves on its own behalf.

Bulk changes come back as one card

A session in the automations workspace can read every automation, run and result, and propose changes to any of them, as one batch. Its trusted status auto-applies the low-risk items (each with Revert). Anything touching scripts, secrets, targets or start-up behavior waits for your accept, item by item.

07Creating & editing with Claude

Describe it first

"New automation" opens a composer. You describe the automation, and a workspace you pick drafts it in a fresh session. A blank form is the fallback.

Review, iterate, approve

The draft returns as a proposal card with Form and YAML views. Ask for changes in plain language, test-run it, then approve.

Editing later

Every automation has an "Ask Claude to change…" bar in its header. The change comes back as a diff to approve. "Edit" opens the same form/YAML editor for direct tweaks.

The draft comes back for review

The same card as a workspace's proposal, plus a Form / YAML switch and an "Ask for changes" box. Iterate in plain language until it's right. Test run runs the draft once against the real tools, without a schedule, and shows the step output and any todos it would post (posted to a scratch view, not your inbox). Approve turns it on.

08Automations in loadouts

Install = approval

Installing a loadout lists its automations in the review you already see for files, scripts and hooks. Ticked ones turn on with the install. One with a missing secret installs off until you add it.

Bound to the workspace

Prompt steps target $self, the workspace the loadout goes into, and use that workspace's vault. The same loadout in two workspaces gives two independent copies.

Synced like loadouts

Remote sources, version stamps and Update ↑ all carry over unchanged. Uninstalling the loadout turns its automations off and removes them. Their run history stays.

Packaged like any other loadout

An automations/ folder joins skills/, commands/ and the other convention folders. Each automation is the same YAML you see in the editor, plus its scripts. It publishes to GHCR with the existing make publish and syncs through the same sources. A prompt step written as workspace: $self binds to whichever workspace the loadout is installed into.

loadouts/webex-ops/
  loadout.md                     # title, version: 1.2.0, tags …
  CLAUDE.md
  skills/webex-thread-reader/SKILL.md
  automations/
    webex-triage/automation.yaml   # same format as the YAML view
    webex-triage/fetch-webex.sh
    webex-mentions/automation.yaml
Updates arrive through the existing Update ↑

A new loadout version shows its automation changes in the review. Same rule as loadout files: anything you edited locally is kept and flagged, never overwritten silently. You choose per automation.

09Ask Claude about a change

One button, every review

"Ask Claude about this" sits on loadout installs and updates, workspace proposals, and drafts. It opens a review conversation beside the changes.

Answers before you ask
