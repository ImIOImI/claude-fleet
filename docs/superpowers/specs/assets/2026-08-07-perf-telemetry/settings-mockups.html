Perf telemetry in Settings — three renderings

Faithful to the post-restyle Settings modal (2026-08-06 design language: mono section headers, toggle rows). The dashed green outline marks the new UI in each option — it is an annotation, not part of the design.  ·  back to the spec

Option A

One row in the existing “Behavior” section

Minimal footprint: telemetry is just the third toggle row under Behavior, styled identically to its neighbors. No live status shown — the MCP perf_status tool is the status surface.

Option B  (recommended)

New “Diagnostics” section with a live status line

Telemetry gets its own section after Plan usage: the recording toggle with a live mono status line (recording state, 24-hour event count, export destination), plus an independent “Export via OTLP” toggle whose endpoint input reveals below it when checked (the Plan-usage-Custom idiom). Export greys out when recording is off. Because the MCP lever can flip recording remotely, the status line — not the checkboxes — is the glanceable source of truth.

Option C

Diagnostics section, all states surfaced

My recommendation is B with C's state handling — the section + status line from B, rendering all three states from C. The extra states are cheap (same status component) and the override state prevents a genuinely confusing situation: a checkbox that appears on while nothing records.
